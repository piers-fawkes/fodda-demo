# Brief: Overage Billing Support in MCP/API Layer

## Context

The app (`app.fodda.ai`) now implements overage billing with soft caps. When a user exceeds their monthly token limit:

- **With card on file**: queries continue at $0.20/token overage (billed monthly via Stripe Meter `fodda_overage_tokens`)
- **Without card**: blocked with a 403 containing a `setupUrl` for one-click card addition

The app's `queryRouter.ts` handles this for queries routed through `app.fodda.ai/api/query`. But MCP traffic via `mcp.fodda.ai` may bypass the app entirely.

## What Needs to Change

### 1. Surface the new 403 format in MCP responses

When the upstream API or account check returns a limit-exceeded error, the MCP response to the user should include:

```json
{
  "error": "Monthly API call limit exceeded. Add a payment method to continue at $0.20/token.",
  "code": "PLAN_LIMIT_EXCEEDED",
  "setupUrl": "https://checkout.stripe.com/...",
  "upgradeUrl": "https://app.fodda.ai?view=billing"
}
```

The `setupUrl` is a one-click Stripe Checkout link (setup mode) that lets the user add a card without logging into the app. It can be generated by calling:

```
POST https://app.fodda.ai/api/account/setup-url
Body: { "email": "user@example.com" } or { "accountId": "recXXX" }
Response: { "ok": true, "setupUrl": "https://..." }
```

### 2. Pass through usage warning headers

The app now returns these headers on successful query responses:

| Header | Value | When |
|--------|-------|------|
| `X-Usage-Warning` | `approaching-limit` | Usage at 80-99% |
| `X-Usage-Percent` | `85` (example) | Usage at 80-99% |
| `X-Usage-Warning` | `overage-active` | Usage at 100%+ with card |
| `X-Usage-Overage-Tokens` | `12` (example) | Usage at 100%+ with card |

If MCP can surface these to the user (e.g. as a note in the response), it helps them know they're approaching or exceeding their limit.

### 3. Account status endpoint already updated

`GET /api/account/status` should continue to work — the `tokens_remaining` field will go negative for overage accounts. No changes needed there, but worth confirming.

### 4. SPT Auth / anonymous agents

For agents using SPT Auth (per-request Stripe payment), this doesn't apply — they pay per request. The overage system only applies to accounts with monthly plans.
